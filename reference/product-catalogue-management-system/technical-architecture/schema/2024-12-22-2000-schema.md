# Product Catalogue Database Schema

## Core Models

### Product
Central model managing both supplier-provided and enriched internal data:
```prisma
model Product {
  id               String   @id @default(cuid())
  name             String
  brand            String
  description      Json     // { supplier, marketing, internal }
  visibility       Json     // { customer, team }
  metadata         Json     // { supplier, externalId, importedAt }
  sourceData       Json     // Raw supplier data
  // Relations
  categories       Category[]
  images           Image[]
  specifications   Specification[]
}
```

### Supporting Models
Models that extend and organize product data:
```prisma
model Category {
  id        String   @id @default(cuid())
  type      String   // 'style' | 'product_type'
  name      String
  productId String
  product   Product  @relation(fields: [productId], references: [id])

  @@unique([productId, type, name])
}

model Image {
  id        String   @id @default(cuid())
  url       String
  source    String   // 'supplier' | 'internal'
  isPrimary Boolean  @default(false)
  productId String
  product   Product  @relation(fields: [productId], references: [id])
}

model Specification {
  id        String   @id @default(cuid())
  name      String
  value     String
  productId String
  product   Product  @relation(fields: [productId], references: [id])

  @@unique([productId, name])
}
```

## Schema Design Principles

### 1. Data Preservation
- Raw supplier data preserved in sourceData JSON
- Original values maintained alongside enriched data
- Complete import history tracked in metadata

### 2. Flexibility
- JSON fields for complex data structures
- Extensible category system
- Flexible specification storage

### 3. Role-Based Access
- Visibility controls at product level
- Separate internal/external descriptions
- Source tracking for images and data
